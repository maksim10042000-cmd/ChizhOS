# ChizhOS — система управления автопарком

Рабочая система учёта аренды автомобилей: автопарки, автомобили, водители, платежи,
расходы, документы, финансы и аналитика.

Система устанавливается **пустой** и рассчитана на ввод реальных данных.
Демонстрационных автомобилей, водителей и денежных операций в ней нет.

---

## Возможности

| Раздел | Что делает |
|---|---|
| **Dashboard** | Автомобили на линии и в простое, доход за день/неделю/месяц, чистая прибыль, задолженность, список событий, требующих внимания |
| **Автомобили** | Карточка авто, фильтры и поиск, статус «на линии / в простое», закрепление водителя, платежи, документы |
| **Водители** | Реестр арендаторов, закреплённые автомобили, доход, долг, дисциплина оплаты |
| **Финансы** | Доходы и расходы по периодам, доходность каждого автомобиля, расчёт процента управляющего, графики |
| **Расходы** | Журнал затрат по категориям: ТО, запчасти, мойка, шиномонтаж, страховка, штрафы, прочее |
| **Календарь** | Платежи по аренде по дням месяца с итогами: начислено / оплачено / долг |
| **Аналитика (KPI)** | Средняя выручка и прибыль на авто, стоимость километра, рейтинги прибыльности и дисциплины |
| **Уведомления** | Просрочка оплаты, приближение ТО, окончание страховки, простой автомобиля |
| **Администрирование** | Пользователи и роли, автопарки, настройки, резервное копирование |

---

## Роли и доступ

| Роль | Доступ |
|---|---|
| **Администратор** | Все автопарки, управление пользователями, настройки, резервные копии |
| **Менеджер парка** | Все разделы, но данные только своего автопарка |
| **Пользователь** | Свой автопарк и только те разделы, которые разрешил администратор |

Разграничение работает **на уровне данных**: выборки в базе сужаются под автопарк
пользователя, а прямые ссылки на запрещённые разделы отбиваются на сервере — не только
скрытием пунктов меню.

## Быстрый старт (локально)

```bash
npm install
```

```bash
cp .env.example .env
```

Откройте `.env` и задайте `ADMIN_PASSWORD`. Затем:

```bash
npm run setup
```

Команда применит миграции, подготовит клиент базы и создаст администратора.

```bash
npm run dev
```

Откройте http://localhost:3000 и войдите под логином и паролем из `.env`.

### Первые шаги в системе

1. **Администрирование → Автопарки** — создайте автопарк.
2. **Администрирование → Пользователи** — заведите сотрудников, назначьте роль и автопарк.
3. **Водители** — добавьте водителей.
4. **Автомобили** — добавьте автомобили, закрепите за ними водителей.
5. В карточке автомобиля вносите платежи, в разделе «Расходы» — затраты.

## Установка на сервер

* **[DEPLOY-TIMEWEB.md](DEPLOY-TIMEWEB.md)** — пошаговая инструкция для **Timeweb Cloud**,
  рассчитанная на человека без опыта администрирования: от создания сервера
  до первого входа, с готовыми командами и чек-листом.
* **[INSTALL.md](INSTALL.md)** — общая инструкция для любого VPS.

Файлы развёртывания в проекте:

| Файл | Назначение |
|---|---|
| `deploy/cloud-init.sh` | Автонастройка сервера при первой загрузке (поле «Cloud-init» в Timeweb) |
| `.env.example` | Образец настроек — из него создаётся `.env` |
| `ecosystem.config.js` | Конфигурация PM2: порт, логи, автоперезапуск |
| `deploy/nginx/chizhos.conf` | Готовый конфиг Nginx с комментариями |
| `deploy/update.sh` | Обновление проекта с резервной копией перед началом |
| `deploy/backup.sh` | Резервное копирование базы и документов |

## Стек

* **Next.js 14** (App Router), **TypeScript**, **Tailwind**
* **Prisma** + **SQLite** (по умолчанию; переход на PostgreSQL описан в INSTALL.md, раздел 19)
* **Recharts** — графики
* **Vitest** — тесты бизнес-логики
* Пароли — **scrypt** из стандартной библиотеки Node: нативные модули не нужны,
  установка не требует компиляторов на сервере

## Структура проекта

```
prisma/schema.prisma          модель данных
scripts/create-admin.ts       создание первого администратора
scripts/backup.ts             резервное копирование из командной строки
src/app/                      страницы: / (вход), /dashboard/*, /admin/*, /logout
src/components/               интерфейс
src/lib/data/repo.ts          доступ к данным и разграничение прав
src/lib/actions.ts            server actions — все изменения данных
src/lib/auth.ts               пароли и токены сессий
src/lib/session.ts            сессии, вход и выход
src/lib/domain/               чистая бизнес-логика + тесты
data/chizhos.db               база данных (создаётся при установке)
public/uploads/               загруженные документы
```

## Хранение данных

| Что | Где |
|---|---|
| База данных | `data/chizhos.db` |
| Документы | `public/uploads/` либо S3/R2, если заполнены переменные `S3_*` |
| Резервные копии | `backups/` |

Резервная копия состоит из **двух частей** — базы данных и папки с документами.
Копировать нужно обе (см. INSTALL.md, раздел 14).
