# Установка ChizhOS на сервер

Пошаговая инструкция. Рассчитана на человека **без опыта системного администрирования**:
каждую команду можно копировать целиком и вставлять в терминал сервера.

Что получится в итоге: система будет открываться по вашему домену, работать по HTTPS,
автоматически запускаться после перезагрузки сервера и делать резервные копии по расписанию.

> **Обозначения.** Строки, начинающиеся с `sudo`, выполняются от администратора сервера.
> Везде, где встречается `example.com`, подставьте свой домен.
> Везде, где встречается `ВАШ_ПАРОЛЬ`, придумайте свой пароль и запишите его в надёжное место.

## 1. Требования к серверу

Подойдёт самый недорогой VPS.

| Параметр | Минимум | Рекомендуется |
|---|---|---|
| Операционная система | Ubuntu 22.04 LTS | Ubuntu 24.04 LTS |
| Оперативная память | 1 ГБ | 2 ГБ |
| Процессор | 1 ядро | 2 ядра |
| Диск | 10 ГБ | 20 ГБ и больше (зависит от объёма документов) |
| Доступ | root или пользователь с `sudo` | то же |

Дополнительно понадобятся:

* **Домен** (например, `chizhos.example.com`), если планируете открывать систему из интернета.
* **SSH-доступ** к серверу — его выдаёт хостинг при создании VPS.

Отдельный сервер базы данных **не нужен**: по умолчанию используется SQLite — вся база
лежит одним файлом внутри проекта.

### Как подключиться к серверу

На своём компьютере откройте терминал (в Windows — PowerShell) и выполните:

```bash
ssh root@IP_АДРЕС_СЕРВЕРА
```

IP-адрес выдаёт хостинг. При первом подключении система спросит подтверждение — введите `yes`.

### Важно: нужен обычный VPS, а не платформа автодеплоя

У некоторых хостингов есть сервисы автоматического деплоя из Git-репозитория
(у Timeweb Cloud это «Приложения» / App Platform, у других — аналоги).
**Для ChizhOS они не подходят.**

На таких платформах при каждом обновлении создаётся новый контейнер, а файловая
система прежнего не сохраняется. Это уничтожило бы и базу данных `data/chizhos.db`,
и все загруженные документы из `public/uploads`.

Берите обычный виртуальный сервер (в Timeweb Cloud — раздел «Облачные серверы»).

### Заметка для Timeweb Cloud

* **Файрвол.** Облачный файрвол по умолчанию не применяется: пока не создана ни одна
  группа правил, разрешён весь трафик — открывать порты 80 и 443 в панели не нужно.
  Если позже создадите группу правил («Сети» → «Firewall»), обязательно добавьте
  готовые типы **SSH**, **HTTP** и **HTTPS**, иначе сайт перестанет открываться.
  Настройка `ufw` из шага 2.6 работает на самом сервере и от панели не зависит.
* **DNS.** Панель → «Домены и SSL» → шестерёнка у домена → вкладка «DNS» →
  «Добавить запись» → тип **A** → IP сервера.
  Домен должен быть делегирован на NS-серверы Timeweb:
  `ns1.timeweb.ru`, `ns2.timeweb.ru`, `ns3.timeweb.org`, `ns4.timeweb.org`.
  Делегирование занимает от 3 до 24 часов — до его завершения выпуск
  SSL-сертификата (раздел 10) не сработает.

## 2. Установка зависимостей

Выполняйте команды по очереди, каждую отдельно.

**2.1. Обновите список пакетов:**

```bash
sudo apt update && sudo apt upgrade -y
```

**2.2. Установите Node.js 20 (на нём работает приложение):**

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
```

```bash
sudo apt install -y nodejs
```

**2.3. Проверьте, что установилось:**

```bash
node -v && npm -v
```

Должны увидеть версию Node не ниже `v20` — например `v20.19.0`.

**2.4. Установите вспомогательные программы:**

```bash
sudo apt install -y git nginx sqlite3 ufw
```

* `git` — для загрузки и обновления проекта,
* `nginx` — принимает запросы из интернета и передаёт их приложению,
* `sqlite3` — для работы с базой данных из командной строки,
* `ufw` — межсетевой экран.

**2.5. Установите PM2 — он будет держать приложение запущенным:**

```bash
sudo npm install -g pm2
```

**2.6. Настройте межсетевой экран:**

```bash
sudo ufw allow OpenSSH && sudo ufw allow 'Nginx Full' && sudo ufw --force enable
```

## 3. Загрузка проекта на сервер

**3.1. Создайте пользователя для приложения** (работать под `root` небезопасно):

```bash
sudo adduser --disabled-password --gecos "" chizhos
```

**3.2. Перейдите в его домашнюю папку:**

```bash
sudo mkdir -p /var/www && sudo chown chizhos:chizhos /var/www
```

**3.3. Скопируйте проект в `/var/www/chizhos`.**

Если проект лежит в Git-репозитории:

```bash
sudo -u chizhos git clone АДРЕС_ВАШЕГО_РЕПОЗИТОРИЯ /var/www/chizhos
```

Если проект у вас папкой на компьютере — загрузите её на сервер. Выполните эту
команду **на своём компьютере**, а не на сервере:

```bash
rsync -av --exclude node_modules --exclude .next --exclude data --exclude backups ./chizhos-app/ root@IP_АДРЕС_СЕРВЕРА:/var/www/chizhos/
```

> Папки `node_modules` и `.next` копировать не нужно и **вредно**: там лежат файлы,
> собранные под вашу операционную систему, на Linux-сервере они не заработают.
> Всё нужное установится на сервере командой из шага 3.4.
> Папки `data` и `backups` — это ваши рабочие данные, при первой установке их ещё нет.

Затем **на сервере** назначьте владельца:

```bash
sudo chown -R chizhos:chizhos /var/www/chizhos
```

**3.4. Перейдите в папку проекта и установите библиотеки:**

```bash
cd /var/www/chizhos && sudo -u chizhos npm ci
```

> **Не добавляйте `--omit=dev`.** Сборка проекта (`npm run build`) и скрипты
> (`create-admin`, `backup`) используют TypeScript, Tailwind, Prisma CLI и tsx —
> они числятся в `devDependencies`. Без них установка оборвётся на шаге сборки.

> Если команда `npm ci` завершилась ошибкой про отсутствующий `package-lock.json`,
> используйте `sudo -u chizhos npm install` .

## 4. Настройка и создание базы данных

**4.1. Создайте файл настроек из образца:**

```bash
cd /var/www/chizhos && sudo -u chizhos cp .env.example .env
```

**4.2. Откройте его для редактирования:**

```bash
sudo -u chizhos nano /var/www/chizhos/.env
```

Заполните значения:

```ini
DATABASE_URL="file:../data/chizhos.db"

ADMIN_LOGIN="admin"
ADMIN_PASSWORD="ВАШ_ПАРОЛЬ"
ADMIN_NAME="Администратор"

ORG_NAME="Название вашей компании"
```

`ADMIN_PASSWORD` — пароль, под которым вы войдёте в систему первый раз.
Придумайте длинный пароль (не менее 12 символов).

Сохранение в редакторе `nano`: **Ctrl+O**, затем **Enter**, затем **Ctrl+X** для выхода.

**4.3. Закройте файл настроек от посторонних** (в нём пароль):

```bash
sudo chmod 600 /var/www/chizhos/.env
```

**4.4. Создайте папку для базы данных:**

```bash
sudo -u chizhos mkdir -p /var/www/chizhos/data
```

Сама база (файл `data/chizhos.db`) создастся автоматически на следующем шаге.

## 5. Миграции

Миграции создают таблицы в базе данных. Выполните:

```bash
cd /var/www/chizhos && sudo -u chizhos npx prisma migrate deploy
```

Затем подготовьте библиотеку доступа к базе:

```bash
cd /var/www/chizhos && sudo -u chizhos npx prisma generate
```

Соберите приложение (это занимает 1–3 минуты):

```bash
cd /var/www/chizhos && sudo -u chizhos npm run build
```

## 6. Создание первого администратора

```bash
cd /var/www/chizhos && sudo -u chizhos npm run create-admin
```

Логин и пароль берутся из файла `.env` (`ADMIN_LOGIN` и `ADMIN_PASSWORD`).

Можно задать их прямо в команде:

```bash
cd /var/www/chizhos && sudo -u chizhos npm run create-admin -- --login=admin --password="ВАШ_ПАРОЛЬ"
```

Скрипт выведет отчёт:

```
✔ Создан администратор «admin».

Состояние базы данных:
  пользователей: 1
  автопарков:    0
  автомобилей:   0
  водителей:     0
```

**Это нормально, что всё по нулям.** Система устанавливается пустой:
никаких демонстрационных автомобилей, водителей и операций в ней нет.
Единственная учётная запись — ваш администратор.

Команду можно запускать повторно: если администратор с таким логином уже есть,
ему просто обновится пароль. Это же — способ восстановить доступ, если пароль забыт
(см. [раздел 12](#12-смена-логина-и-пароля-администратора)).

## 7. Первый запуск и проверка

**7.1. Запустите приложение:**

```bash
cd /var/www/chizhos && sudo -u chizhos pm2 start npm --name chizhos -- start
```

**7.2. Проверьте, что оно отвечает:**

```bash
curl -I http://localhost:3000
```

Должны увидеть строку `HTTP/1.1 200 OK` или `HTTP/1.1 307 Temporary Redirect` — обе означают,
что приложение работает.

**7.3. Посмотреть журнал работы** (если что-то не так):

```bash
pm2 logs chizhos --lines 50
```

Выход из просмотра журнала — **Ctrl+C**.

## 8. Автозапуск после перезагрузки сервера

Чтобы система поднималась сама после перезагрузки или сбоя питания:

**8.1. Сохраните текущий список запущенных приложений:**

```bash
sudo -u chizhos pm2 save
```

**8.2. Включите автозапуск:**

```bash
sudo pm2 startup systemd -u chizhos --hp /home/chizhos
```

Команда выведет ещё одну команду — скопируйте и выполните её, если она появится.

**8.3. Проверьте:**

```bash
sudo reboot
```

Сервер перезагрузится, связь оборвётся. Подключитесь снова через минуту и проверьте:

```bash
pm2 list
```

В списке должно быть приложение `chizhos` со статусом `online`.

### Полезные команды управления

```bash
pm2 restart chizhos    # перезапустить
```

```bash
pm2 stop chizhos       # остановить
```

```bash
pm2 start chizhos      # запустить снова
```

```bash
pm2 list               # статус всех приложений
```

## 9. Подключение домена

**9.1. В панели управления доменом** (там, где вы его купили) создайте запись типа **A**:

| Поле | Значение |
|---|---|
| Тип | A |
| Имя | `@` для `example.com` либо `chizhos` для `chizhos.example.com` |
| Значение | IP-адрес вашего сервера |
| TTL | 3600 (или «авто») |

Изменения расходятся по интернету от 10 минут до нескольких часов.

**9.2. Проверьте, что домен указывает на сервер:**

```bash
ping -c 2 example.com
```

В ответе должен быть IP-адрес вашего сервера.

**9.3. Создайте настройку nginx:**

```bash
sudo nano /etc/nginx/sites-available/chizhos
```

Вставьте (заменив `example.com` на свой домен):

```nginx
server {
    listen 80;
    server_name example.com www.example.com;

    # Ограничение на размер загружаемого документа.
    client_max_body_size 25M;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}
```

Сохраните: **Ctrl+O**, **Enter**, **Ctrl+X**.

**9.4. Включите настройку и перезапустите nginx:**

```bash
sudo ln -s /etc/nginx/sites-available/chizhos /etc/nginx/sites-enabled/
```

```bash
sudo rm -f /etc/nginx/sites-enabled/default
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

`nginx -t` проверяет настройку. Если написано `syntax is ok` и `test is successful` — всё верно.

**9.5. Откройте в браузере `http://example.com`** — должна появиться страница входа.

## 10. Включение HTTPS

HTTPS (замочек в адресной строке) обязателен: без него логины и пароли передаются
по сети в открытом виде.

**10.1. Установите Certbot:**

```bash
sudo apt install -y certbot python3-certbot-nginx
```

**10.2. Получите сертификат** (бесплатный, от Let's Encrypt):

```bash
sudo certbot --nginx -d example.com -d www.example.com
```

Certbot задаст вопросы:

* **e-mail** — укажите свою почту (на неё придёт напоминание, если сертификат перестанет обновляться);
* **согласие с условиями** — введите `Y`;
* **рассылка** — можно `N`;
* **перенаправление HTTP → HTTPS** — выберите вариант **2 (Redirect)**.

**10.3. Проверьте:** откройте `https://example.com` — в адресной строке появится замочек.

## 11. Обновление SSL-сертификатов

Сертификаты Let's Encrypt действуют 90 дней. Certbot обновляет их **сам** —
при установке он создаёт системный таймер.

**Проверить, что автообновление настроено:**

```bash
sudo systemctl status certbot.timer
```

Должно быть `active (waiting)`.

**Проверить обновление вручную (без реальной перевыпуска):**

```bash
sudo certbot renew --dry-run
```

Если написано `Congratulations, all simulated renewals succeeded` — всё в порядке.

**Обновить принудительно, если что-то сломалось:**

```bash
sudo certbot renew --force-renewal && sudo systemctl reload nginx
```

## 12. Смена логина и пароля администратора

### Способ 1 — из интерфейса (обычный)

1. Войдите в систему.
2. **Администрирование → Настройки → Мой пароль** — смена своего пароля.
3. **Администрирование → Пользователи → Изменить** — смена логина и имени.
4. **Администрирование → Пользователи → Пароль** — смена пароля любому пользователю.

После смены пароля все сессии этого пользователя завершаются: на других
устройствах потребуется войти заново.

### Способ 2 — с сервера (если пароль забыт)

```bash
cd /var/www/chizhos && sudo -u chizhos npm run create-admin -- --login=admin --password="НОВЫЙ_ПАРОЛЬ"
```

Если пользователь `admin` существует — ему установится новый пароль и вернутся права
администратора. Если нет — он будет создан.

**После этого обязательно** обновите `ADMIN_PASSWORD` в файле `.env`, чтобы там
не оставался старый пароль:

```bash
sudo -u chizhos nano /var/www/chizhos/.env
```

## 13. Создание пользователей, роли, автопарки

### 13.1. Сначала — автопарк

Каждый пользователь (кроме администратора) привязан к автопарку и видит **только его данные**.
Поэтому начинать нужно с парков.

1. Войдите как администратор.
2. **Администрирование → Автопарки → Добавить парк**.
3. Введите название, например «Парк №1 — Москва», нажмите **Создать парк**.

Название парка можно изменить прямо в поле списка — оно обновится во всех разделах.
Удалить парк можно, только если в нём не осталось автомобилей и пользователей.

### 13.2. Создание пользователя

1. **Администрирование → Пользователи → Добавить пользователя**.
2. Заполните:
   * **Логин** — латинские буквы, цифры и символы `.` `_` `-` `@`;
   * **Имя / ФИО** — как показывать в интерфейсе;
   * **Пароль** — не короче 6 символов (передайте его сотруднику, он сможет сменить сам);
   * **Роль** — см. таблицу ниже;
   * **Автопарк** — обязателен для всех ролей, кроме администратора.
3. Нажмите **Создать пользователя**.

### 13.3. Роли

| Роль | Что доступно |
|---|---|
| **Администратор** | Всё: все автопарки, управление пользователями, настройки, резервные копии |
| **Менеджер парка** | Все разделы, но данные **только своего автопарка** |
| **Пользователь** | Только свой автопарк и **только те разделы**, которые отмечены администратором |

Для роли **Пользователь** в форме появляется блок «Доступные разделы» — отметьте галочками,
что человеку можно видеть: Dashboard, Автомобили, Водители, Финансы, Расходы, Календарь,
Аналитика, Уведомления.

Неотмеченные разделы не появятся в меню и **будут недоступны по прямой ссылке** —
ограничение действует на сервере, а не только в интерфейсе.

### 13.4. Смена автопарка у пользователя

**Администрирование → Пользователи → Изменить → поле «Автопарк»**.
После сохранения пользователь сразу начнёт видеть данные нового парка, а данные прежнего
станут для него недоступны.

### 13.5. Блокировка и удаление

* **Блокировать** — учётная запись сохраняется, но вход запрещён, активные сессии обрываются.
  Подходит, когда сотрудник ушёл в отпуск или уволился, а его данные нужно сохранить.
* **Удалить** — учётная запись удаляется безвозвратно.

Систему нельзя оставить без администратора: последнего администратора не получится
удалить, заблокировать или понизить в роли. Свою собственную учётную запись
удалить или заблокировать тоже нельзя.

### 13.6. Что делать дальше

После создания парков и пользователей можно вносить рабочие данные:

1. **Водители** → «Добавить водителя» — ФИО, телефон, права, паспорт, залог.
2. **Автомобили** → «Добавить автомобиль» — госномер, марка, модель, парк.
   Здесь же закрепляется водитель, указывается ставка аренды, дата окончания страховки
   и пробег следующего ТО (из них система сама построит напоминания).
3. **Карточка автомобиля** (клик по строке) → «Внести платёж» — начисление аренды.
   Неоплаченные платежи автоматически формируют задолженность и просрочку.
4. **Расходы** → «Добавить расход» — ТО, запчасти, мойка, страховка, штрафы.
5. **Документы** — загружаются в карточке автомобиля (СТС, ПТС, договор, полис)
   и в блоке документов водителя.

## 14. Резервное копирование

Полная копия системы состоит из **двух частей**:

1. **База данных** — все автопарки, автомобили, водители, платежи, расходы, пользователи.
2. **Файлы документов** — сканы и фотографии, загруженные в карточки.

Копировать нужно **обе**.

### 14.1. Способ 1 — из интерфейса (простой)

**Администрирование → Резервное копирование → Скачать резервную копию.**

Скачается файл вида `chizhos-backup-2026-07-27.json` — сохраните его на свой компьютер
или в облако. В нём вся база, кроме самих файлов документов.

### 14.2. Способ 2 — с сервера

```bash
cd /var/www/chizhos && sudo -u chizhos npm run backup
```

Копия сохранится в `/var/www/chizhos/backups/chizhos-backup-ГГГГ-ММ-ДД.json`.

### 14.3. Копия файла базы данных целиком

Самый надёжный вариант для SQLite — команда `.backup`, она корректно работает
даже во время работы приложения:

```bash
sudo -u chizhos sqlite3 /var/www/chizhos/data/chizhos.db ".backup '/var/www/chizhos/backups/chizhos-$(date +%F).db'"
```

### 14.4. Копия загруженных документов

```bash
sudo tar -czf /var/www/chizhos/backups/uploads-$(date +%F).tar.gz -C /var/www/chizhos/public uploads
```

### 14.5. Автоматические копии по расписанию

Настроим ежедневное копирование в 3:30 ночи с хранением за 30 дней.

**Создайте скрипт:**

```bash
sudo nano /usr/local/bin/chizhos-backup.sh
```

Вставьте:

```bash
#!/bin/bash
set -e
APP=/var/www/chizhos
DEST=$APP/backups
DATE=$(date +%F)

mkdir -p "$DEST"

# База данных
sqlite3 "$APP/data/chizhos.db" ".backup '$DEST/chizhos-$DATE.db'"

# Загруженные документы
tar -czf "$DEST/uploads-$DATE.tar.gz" -C "$APP/public" uploads 2>/dev/null || true

# Удаляем копии старше 30 дней
find "$DEST" -name 'chizhos-*.db' -mtime +30 -delete
find "$DEST" -name 'uploads-*.tar.gz' -mtime +30 -delete

echo "$(date '+%F %T') backup ok"
```

Сохраните и сделайте скрипт исполняемым:

```bash
sudo chmod +x /usr/local/bin/chizhos-backup.sh
```

**Добавьте в расписание:**

```bash
sudo crontab -e
```

При первом запуске редактор спросит, какой использовать — выберите `1` (nano).
Добавьте в конец файла строку:

```
30 3 * * * /usr/local/bin/chizhos-backup.sh >> /var/log/chizhos-backup.log 2>&1
```

Сохраните: **Ctrl+O**, **Enter**, **Ctrl+X**.

**Проверьте, что скрипт работает:**

```bash
sudo /usr/local/bin/chizhos-backup.sh && ls -lh /var/www/chizhos/backups/
```

> **Важно.** Копии на том же сервере не спасут при отказе диска или потере сервера.
> Настройте выгрузку папки `backups` на другой носитель — в облако, на второй сервер
> или скачивайте вручную раз в неделю командой (выполняется **на вашем компьютере**):
>
> ```bash
> scp -r root@IP_АДРЕС_СЕРВЕРА:/var/www/chizhos/backups ./chizhos-backups
> ```

## 15. Восстановление из резервной копии

### 15.1. Из JSON-файла через интерфейс

1. **Администрирование → Резервное копирование → Восстановить из файла**.
2. Выберите файл `chizhos-backup-….json`.
3. Подтвердите предупреждение.

> **Внимание.** Восстановление **полностью заменяет** текущее содержимое базы:
> автомобили, водителей, платежи, расходы, документы и пользователей.
> Операция выполняется одной транзакцией: при ошибке база останется нетронутой.

После восстановления войдите заново — пароли будут те, что действовали на момент копии.

### 15.2. Из файла базы данных (полное восстановление)

**15.2.1. Остановите приложение:**

```bash
pm2 stop chizhos
```

**15.2.2. Сохраните текущую базу на всякий случай:**

```bash
sudo -u chizhos cp /var/www/chizhos/data/chizhos.db /var/www/chizhos/data/chizhos.db.before-restore
```

**15.2.3. Положите копию на место рабочей базы** (подставьте нужную дату):

```bash
sudo -u chizhos cp /var/www/chizhos/backups/chizhos-2026-07-27.db /var/www/chizhos/data/chizhos.db
```

**15.2.4. Восстановите документы:**

```bash
sudo tar -xzf /var/www/chizhos/backups/uploads-2026-07-27.tar.gz -C /var/www/chizhos/public
```

```bash
sudo chown -R chizhos:chizhos /var/www/chizhos/public/uploads /var/www/chizhos/data
```

**15.2.5. Запустите приложение:**

```bash
pm2 start chizhos
```

## 18. Где хранятся документы и загруженные файлы

### 18.1. По умолчанию — на диске сервера

| Что | Где лежит |
|---|---|
| База данных | `/var/www/chizhos/data/chizhos.db` |
| Документы (сканы, фото, PDF) | `/var/www/chizhos/public/uploads/` |
| Резервные копии | `/var/www/chizhos/backups/` |
| Журнал работы приложения | `pm2 logs chizhos` |
| Настройки | `/var/www/chizhos/.env` |

Записи о документах хранятся в базе, а сами файлы — в папке `public/uploads`.
Поэтому копировать нужно и базу, и папку.

Ограничение на размер одного файла — 25 МБ (задаётся в `src/app/api/upload/route.ts`
и в `client_max_body_size` в настройке nginx).

**Посмотреть, сколько места занимают документы:**

```bash
du -sh /var/www/chizhos/public/uploads
```

### 18.2. Хранение в облаке (необязательно)

Если документов много, их можно хранить в S3-совместимом хранилище
(Cloudflare R2, AWS S3, MinIO, Selectel, VK Cloud). Заполните в `.env`:

```ini
S3_ENDPOINT="https://<идентификатор>.r2.cloudflarestorage.com"
S3_REGION="auto"
S3_BUCKET="chizhos-docs"
S3_ACCESS_KEY_ID="ключ"
S3_SECRET_ACCESS_KEY="секрет"
S3_PUBLIC_URL="https://docs.example.com"
```

и перезапустите приложение:

```bash
pm2 restart chizhos
```

Если блок `S3_*` пуст, файлы сохраняются на диск сервера — менять код не нужно.
Уже загруженные ранее файлы останутся на диске; в облако попадут только новые.

## 19. Переход на PostgreSQL (необязательно)

SQLite полностью подходит для одной компании: сотни автомобилей и десятки
пользователей она держит без проблем. PostgreSQL имеет смысл, если планируется
несколько серверов приложения или очень большой объём данных.

**19.1. Установите PostgreSQL:**

```bash
sudo apt install -y postgresql
```

**19.2. Создайте базу и пользователя:**

```bash
sudo -u postgres psql -c "CREATE USER chizhos WITH PASSWORD 'ВАШ_ПАРОЛЬ';"
```

```bash
sudo -u postgres psql -c "CREATE DATABASE chizhos OWNER chizhos;"
```

**19.3. Укажите провайдер в схеме.** Откройте файл:

```bash
sudo -u chizhos nano /var/www/chizhos/prisma/schema.prisma
```

Замените `provider = "sqlite"` на `provider = "postgresql"`.

**19.4. Пропишите адрес базы в `.env`:**

```ini
DATABASE_URL="postgresql://chizhos:ВАШ_ПАРОЛЬ@localhost:5432/chizhos?schema=public"
```

**19.5. Создайте таблицы заново и запустите:**

```bash
cd /var/www/chizhos && sudo -u chizhos rm -rf prisma/migrations && sudo -u chizhos npx prisma migrate dev --name init
```

```bash
cd /var/www/chizhos && sudo -u chizhos npm run create-admin && sudo -u chizhos npm run build && pm2 restart chizhos
```

> Данные из SQLite при этом **не переносятся автоматически**. Если в системе уже есть
> рабочие данные: сначала выгрузите их через **Администрирование → Резервное копирование →
> Скачать резервную копию**, затем после перехода на PostgreSQL загрузите этот файл
> через **Восстановить из файла**.

Резервное копирование PostgreSQL выполняется другой командой:

```bash
sudo -u postgres pg_dump chizhos > /var/www/chizhos/backups/chizhos-$(date +%F).sql
```

## 20. Если что-то пошло не так

### Сайт не открывается

```bash
pm2 list
```

Если `chizhos` не в статусе `online`:

```bash
pm2 restart chizhos && pm2 logs chizhos --lines 50
```

Проверьте nginx:

```bash
sudo nginx -t && sudo systemctl status nginx
```

### Ошибка «502 Bad Gateway»

Nginx работает, а приложение — нет. Проверьте:

```bash
curl -I http://localhost:3000
```

Если ответа нет — смотрите журнал `pm2 logs chizhos --lines 50`.
Частая причина — порт в настройке nginx не совпадает с портом приложения.

### Забыт пароль администратора

См. [раздел 12, способ 2](#12-смена-логина-и-пароля-администратора).

### Ошибки базы данных при запуске

Проверьте, что миграции применены и права на файлы верные:

```bash
cd /var/www/chizhos && sudo -u chizhos npx prisma migrate deploy
```

```bash
sudo chown -R chizhos:chizhos /var/www/chizhos/data
```

### Не загружаются документы

Проверьте права на папку:

```bash
sudo mkdir -p /var/www/chizhos/public/uploads && sudo chown -R chizhos:chizhos /var/www/chizhos/public/uploads
```

Если файл больше 25 МБ — увеличьте `client_max_body_size` в настройке nginx
и константу `MAX_SIZE` в `src/app/api/upload/route.ts`.

### Закончилось место на диске

```bash
df -h && du -sh /var/www/chizhos/*
```

Чаще всего место занимают старые резервные копии в `backups` — их можно удалять.
