# CLAUDE.md — контекст проекта для Claude Code

Этот файл Claude Code читает автоматически при запуске в этой папке.

## Что это
**ChizhOS** — рабочая (не демонстрационная) система управления автопарком: аренда авто,
водители, платежи, расходы, документы, аналитика.

Система устанавливается **пустой**: ни автомобилей, ни водителей, ни операций, ни парков.
Единственная учётная запись после установки — администратор, созданный скриптом
`npm run create-admin`. Демо-данных в проекте нет и добавлять их не нужно.

## Стек
Next.js 14 (App Router) · TypeScript · Tailwind · Prisma (SQLite по умолчанию) · Recharts · Vitest.
Документы — на диск сервера (`public/uploads`) либо в S3/R2, если заполнены переменные `S3_*`.

## Команды
```bash
npm install
npm run setup        # миграции + prisma generate + создание администратора
npm run dev          # http://localhost:3000
npm run typecheck    # tsc --noEmit
npm test             # юнит-тесты доменной логики (Vitest)
npm run build        # прод-сборка (включает prisma generate)
npm run create-admin # создать администратора либо сбросить ему пароль
npm run backup       # выгрузка всех данных в backups/*.json
npm run db:studio    # просмотр базы в браузере
```

## Маршруты
- `/` — страница входа (логин + пароль). Вошедшего сразу уводит в его первый доступный раздел.
- `/dashboard`, `/dashboard/{cars,drivers,finance,expenses,calendar,analytics,notifications}` — рабочие разделы.
- `/admin`, `/admin/{parks,settings,backup}` — администрирование, только для роли admin.
- `/logout` — выход (route handler; кнопка «Выйти» вызывает server action `logoutAction`).

## С чего начинать чтение (точки входа)
- `prisma/schema.prisma` — модель данных. SQLite не поддерживает enum, перечисления хранятся строками.
- `src/lib/data/repo.ts` — ЕДИНСТВЕННОЕ место, знающее о Prisma. Здесь же реализовано разграничение доступа.
- `src/lib/actions.ts` — Server Actions (все мутации) с проверкой прав.
- `src/lib/auth.ts` — хеширование паролей (scrypt из стандартной библиотеки Node, без нативных модулей).
- `src/lib/session.ts` — сессии в БД + cookie; `getSession()` обёрнут в `cache()`.
- `src/lib/current.ts` — `requireSession` / `requireAdmin` / `requireSection` / `currentContext`.
- `src/lib/domain/` — ЧИСТАЯ бизнес-логика (finance, overdue, notifications, kpi) + тесты.
- `src/lib/types.ts` — доменные типы, роли, список разделов; импортируется и клиентом, и сервером.
- `src/app/globals.css` — дизайн-система.

## Роли
- `admin` — всё, все парки, управление пользователями и настройками.
- `manager` — все разделы, но данные только своего парка.
- `user` — свой парк и только разделы из `permissions` (CSV в БД, пусто = `DEFAULT_USER_SECTIONS`).

## Архитектурные принципы (соблюдать при доработках)
- Бизнес-логика — только чистые функции в `src/lib/domain` (без React, без БД). Их зовут страницы, действия и тесты.
- Все мутации — через Server Actions в `src/lib/actions.ts`, с проверкой прав и `revalidatePath("/", "layout")`.
- Разграничение доступа — «на уровне данных»: выборки в `repo.ts` сужаются под парк сессии.
  UI не дублирует проверки, а прямые ссылки на запрещённые разделы отбивает `requireSection`.
- Клиентские компоненты не импортируют серверные модули (`session`/`repo`/`current`/`storage`).
- **Не выдумывать данные.** Если поле не заполнено (страховка, пробег ТО, прошлый период) —
  показывать «не указано» / «нет данных», а не подставлять правдоподобное число.
  Проценты роста считаются функцией `deltaPct`, которая возвращает `null`, когда сравнивать не с чем.
- Каждый раздел, таблица и график обязаны иметь пустое состояние, объясняющее следующий шаг.

## Что реализовано
Аутентификация по логину/паролю, сессии в БД, три роли с правами на разделы, управление
пользователями (создание, блокировка, смена логина/пароля/роли/парка/прав), автопарки,
автомобили с закреплением водителя, водители, платежи по аренде с расчётом просрочки,
расходы, документы (загрузка/замена/удаление), финансы с расчётом управляющего, аналитика KPI,
календарь платежей, уведомления, резервное копирование (интерфейс + CLI), адаптивная вёрстка
с выдвижным меню, тесты доменной логики.
