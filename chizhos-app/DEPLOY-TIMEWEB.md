# Запуск ChizhOS на Timeweb Cloud

Пошаговая инструкция для человека **без опыта** в программировании, Linux и администрировании.

Каждую команду можно копировать целиком и вставлять в терминал. Ничего решать самостоятельно
не нужно — все значения уже подобраны под этот проект.

**Сколько времени займёт:** около 1 часа, из них 15–20 минут — ожидание установки и сборки.

---

## Что это за проект (результат анализа)

Прежде чем начать, коротко о том, что мы разворачиваем — от этого зависят все шаги ниже.

| Что | Значение | Почему это важно |
|---|---|---|
| Тип приложения | Next.js 14, серверный рендеринг | Это **не** набор HTML-файлов. Нужен постоянно работающий процесс Node.js |
| Язык | TypeScript | Перед запуском проект нужно **собрать** |
| Стили | Tailwind CSS | Собирается вместе с проектом |
| Графики | Recharts 3 | Отдельной настройки не требует |
| База данных | SQLite через Prisma, 10 таблиц | Отдельный сервер БД **не нужен** — вся база это один файл `data/chizhos.db` |
| Менеджер пакетов | **npm** (есть `package-lock.json`) | Ставим через `npm ci`, не через yarn/pnpm |
| Node.js | **версия 20** (минимум 18.17) | Указано в `package.json` → `engines` |
| Сборка | `npm run build` = `prisma generate && next build` | Результат складывается в папку `.next` |
| Запуск | `npm start` = `next start`, порт 3000 | Порт 3000 доступен только внутри сервера |
| Docker | **не используется** | Разворачиваем напрямую, без контейнеров |
| Nginx | **нужен** | Принимает запросы из интернета и передаёт приложению; через него же работает HTTPS |
| PM2 | **нужен** | Держит приложение запущенным и поднимает после перезагрузки сервера |
| Переменные окружения | файл `.env` | Обязательны `DATABASE_URL` и `ADMIN_PASSWORD` |

### Файлы для развёртывания уже в проекте

| Файл | Назначение |
|---|---|
| `deploy/cloud-init.sh` | Автоматическая подготовка сервера при первой загрузке (см. пункт 1.4) |
| `.env.example` | Образец настроек, из него делаем `.env` |
| `ecosystem.config.js` | Настройка PM2 (имя, порт, логи, автоперезапуск) |
| `deploy/nginx/chizhos.conf` | Готовый конфиг Nginx с комментариями |
| `deploy/update.sh` | Безопасное обновление проекта с резервной копией |
| `deploy/backup.sh` | Резервное копирование базы и документов |
| `scripts/create-admin.ts` | Создание администратора (и сброс пароля) |

### Главное предупреждение

У Timeweb Cloud есть услуга **«Приложения» (App Platform)** — автодеплой из Git.
**Она не подойдёт.** В её документации сказано: «каждый новый деплой запускает новое
окружение, то есть создаётся новый Docker-контейнер, в котором данные из предыдущих
версий контейнера не сохраняются».

Для ChizhOS это означает, что при каждом обновлении **стёрлись бы и база `data/chizhos.db`,
и все загруженные документы**. Нужен раздел **«Облачные серверы»** — обычный VPS.

## 1. Подготовка сервера

### 1.1. Создание сервера

Зайдите в панель Timeweb Cloud → раздел **«Облачные серверы»** → кнопка **«Создать»**.

### 1.2. Какие параметры выбрать

| Параметр | Что выбрать | Пояснение |
|---|---|---|
| **Тип** | Облачный сервер (не «Приложение») | См. предупреждение выше |
| **Операционная система** | **Ubuntu 24.04 LTS** | LTS = долгая поддержка. Все команды инструкции написаны под неё |
| **Процессор (CPU)** | **2 ядра** | 1 ядра хватит для работы, но сборка проекта будет идти 5–7 минут вместо 2 |
| **Оперативная память (RAM)** | **2 ГБ** | Минимум для сборки Next.js. На 1 ГБ сборка может прерваться с ошибкой нехватки памяти |
| **Диск (SSD/NVMe)** | **30 ГБ** | ~2 ГБ занимает система, ~1,5 ГБ проект с библиотеками, остальное — документы и резервные копии |
| **Локация** | Санкт-Петербург или Москва | Ближе к пользователям — быстрее открывается |
| **Сеть** | Публичный IPv4 — **включить** | Без него сервер не будет доступен из интернета |
| **Резервные копии** | Включить, если не жалко ~10% стоимости | Снимки всего сервера. Не отменяют копий из раздела 16 |
| **Способ входа** | **SSH-ключ** (надёжнее) либо пароль на почту | Ниже описаны оба варианта |

Тариф ориентировочно 2 CPU / 2 ГБ / 30 ГБ — этого достаточно для автопарка
в несколько сотен машин и десятков пользователей.

### 1.3. Что включать НЕ нужно

* **Файрвол в панели** — трогать не нужно. Пока не создана ни одна группа правил,
  разрешён весь трафик. Защиту настроим на самом сервере.
* **Балансировщик, приватная сеть, дополнительные диски** — для одного сервера не требуются.

### 1.4. Cloud-init — автоматическая настройка (рекомендуется)

В форме создания сервера есть поле **«Cloud-init»** с подписью
«Автоматизируйте первоначальную настройку сервера, загрузив собственный скрипт».

Для ChizhOS такой скрипт готов: **`deploy/cloud-init.sh`**. Если его вставить,
сервер при первой загрузке **сам выполнит весь раздел 3** этой инструкции.

**Что сделает скрипт:**

| Действие | Зачем |
|---|---|
| Обновит систему | Свежие версии пакетов |
| Установит Node.js 20 | На нём работает приложение |
| Установит Nginx, Git, SQLite3, Certbot, UFW | Всё необходимое окружение |
| Установит PM2 | Держит приложение запущенным |
| Создаст файл подкачки 2 ГБ | Иначе сборка падает с ошибкой нехватки памяти |
| Создаст пользователя `chizhos` и папки | Запускать сайт от `root` небезопасно |
| Настроит межсетевой экран | Откроет только SSH и веб-порты |

**Чего скрипт не делает** (это требует ваших данных): не заполняет `.env`,
не устанавливает зависимости, не собирает проект, не настраивает домен.

**Как использовать:**

1. Откройте файл `deploy/cloud-init.sh` из проекта в любом текстовом редакторе
   (Блокнот, VS Code, TextEdit).
2. **Необязательно:** если проект лежит в **открытом** Git-репозитории, впишите его
   адрес в строку `REPO_URL=""` в начале файла — тогда код скачается автоматически.
   Для закрытого репозитория оставьте пустым: скрипт не сможет ввести пароль.
3. Выделите **всё содержимое файла** (Ctrl+A / Cmd+A) и скопируйте.
4. Вставьте в поле **«Cloud-init»** в форме создания сервера Timeweb.
5. Создайте сервер.

> **Первая строка файла — `#!/bin/sh` — обязательна.** Панель Timeweb принимает
> только скрипты, начинающиеся с `#!/bin/sh` или `#cloud-config`, иначе поле
> покажет ошибку. Не удаляйте эту строку и не добавляйте ничего перед ней —
> даже пустую строку или комментарий.
>
> По этой же причине скрипт написан на POSIX sh (в Ubuntu его выполняет `dash`),
> без специфичных для bash конструкций.

**Важно:** скрипт выполняется 3–6 минут **после** того, как сервер уже показан
как «активен». Подключиться по SSH можно сразу, но команды `node -v` и `pm2 -v`
заработают только после завершения настройки.

**Как проверить, что скрипт отработал** (после подключения по SSH):

```bash
cat /root/CHIZHOS-NEXT-STEPS.txt
```

Появится отчёт с установленными версиями и списком дальнейших шагов.
Если файла нет — настройка ещё идёт либо произошла ошибка, смотрите журнал:

```bash
tail -30 /var/log/cloud-init-output.log
```

> **Если вы не используете Cloud-init** — ничего страшного, просто выполните
> раздел 3 вручную, командой за командой. Результат будет тот же.

После создания сервера панель покажет его **IP-адрес** — вида `81.90.123.45`.
Запишите его, он понадобится дальше. В инструкции он обозначен как `IP_СЕРВЕРА`.

## 2. Подключение к серверу

Подключаться будем по SSH — это способ управлять сервером текстовыми командами.

### 2.1. Как открыть терминал на Windows

1. Нажмите **Win + R**.
2. Введите `powershell` и нажмите **Enter**.
3. Откроется синее окно — это и есть терминал.

> PowerShell есть во всех Windows 10 и 11, ничего доустанавливать не нужно.

### 2.2. Как открыть терминал на macOS

1. Нажмите **Cmd + Пробел**.
2. Введите `Терминал` (или `Terminal`) и нажмите **Enter**.

### 2.3. Вход на сервер

В открывшемся окне введите команду, подставив свой IP:

```bash
ssh root@IP_СЕРВЕРА
```

Что произойдёт дальше:

1. **При первом подключении** появится вопрос вида
   `Are you sure you want to continue connecting (yes/no)?`
   Введите `yes` и нажмите **Enter**. Это подтверждение, что вы доверяете серверу.

2. Появится строка `root@IP_СЕРВЕРА's password:`
   Введите пароль от сервера (его прислали на почту при создании).

   **Важно:** при вводе пароля на экране **ничего не отображается** — ни точек, ни звёздочек.
   Это нормально, просто печатайте вслепую и нажмите **Enter**.

3. Если всё верно, увидите приглашение вида:

   ```
   root@chizhos-server:~#
   ```

   Значит, вы внутри сервера. Все следующие команды выполняются здесь.

### 2.4. Проверка, что всё работает

```bash
whoami && hostname -I && df -h / && free -h
```

Что покажет:
* `root` — вы вошли с полными правами;
* IP-адрес сервера;
* сколько места на диске (столбец `Avail` — свободно);
* сколько оперативной памяти (столбец `available`).

Если видите эти данные — подключение работает, продолжаем.

> **Как выйти с сервера:** команда `exit` или сочетание **Ctrl + D**.
> Чтобы вернуться — снова `ssh root@IP_СЕРВЕРА`.

## 3. Установка программ на сервер

> **Если вы вставляли скрипт Cloud-init (пункт 1.4) — этот раздел можно пропустить**
> и переходить сразу к разделу 4. Проверить, что всё установлено:
>
> ```bash
> node -v && npm -v && pm2 -v && nginx -v
> ```
>
> Если команды отвечают версиями — раздел выполнен автоматически.
> Если пишут «command not found» — подождите 2–3 минуты (скрипт ещё работает)
> либо выполните раздел вручную.

Выполняйте команды **по одной**, дожидаясь завершения каждой.

### 3.1. Обновление системы

```bash
apt update && apt upgrade -y
```

Скачивает свежие версии системных пакетов. Занимает 1–3 минуты.
Если появится синий экран с вопросом о перезапуске служб — нажмите **Enter** (вариант по умолчанию).

### 3.2. Установка Node.js 20

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
```

```bash
apt install -y nodejs
```

### 3.3. Проверка Node.js

```bash
node -v && npm -v
```

Должно показать версию Node не ниже `v20.0.0` — например `v20.19.0`, и версию npm.
**Если версия ниже 18.17 — проект не запустится**, повторите шаг 3.2.

### 3.4. Установка остальных программ

```bash
apt install -y nginx git sqlite3 ufw rsync
```

Что устанавливается и зачем:

| Программа | Зачем нужна |
|---|---|
| `nginx` | Принимает запросы из интернета и передаёт приложению |
| `git` | Загрузка и обновление кода проекта |
| `sqlite3` | Работа с базой данных из командной строки, создание копий |
| `ufw` | Межсетевой экран — закрывает лишние порты |
| `rsync` | Копирование файлов с вашего компьютера на сервер |

### 3.5. Установка PM2

```bash
npm install -g pm2
```

PM2 — менеджер процессов: следит, чтобы приложение работало постоянно.

### 3.6. Настройка межсетевого экрана

```bash
ufw allow OpenSSH
```

```bash
ufw allow 'Nginx Full'
```

```bash
ufw --force enable
```

Открываем только два входа: SSH (чтобы вы могли управлять сервером) и веб (порты 80 и 443).
Порт 3000, на котором работает приложение, остаётся закрытым снаружи — обращаться к нему
будет только Nginx изнутри сервера.

Проверка:

```bash
ufw status
```

Должны увидеть строки `OpenSSH ALLOW` и `Nginx Full ALLOW`.

### 3.7. Создание отдельного пользователя для приложения

Запускать сайт от имени `root` небезопасно: если в приложении найдут уязвимость,
злоумышленник получит полный контроль над сервером. Создаём ограниченного пользователя.

```bash
adduser --disabled-password --gecos "" chizhos
```

```bash
mkdir -p /var/www && chown chizhos:chizhos /var/www
```

## 4. Загрузка проекта

Есть три способа. **Для ChizhOS рекомендуется способ А (Git)** — он же делает
возможным обновление одной командой в будущем.

### Способ А — через Git (рекомендуется)

Подходит, если проект лежит в GitHub / GitLab / Timeweb Git.

```bash
sudo -u chizhos git clone АДРЕС_ВАШЕГО_РЕПОЗИТОРИЯ /var/www/chizhos
```

Например:

```bash
sudo -u chizhos git clone https://github.com/username/chizhos-app.git /var/www/chizhos
```

Если репозиторий закрытый, Git попросит логин и пароль (или токен доступа).

**Почему этот способ лучше:** обновление позже будет выполняться одной командой
`git pull`, а скрипт `deploy/update.sh` сделает всё остальное автоматически.

### Способ Б — через архив

Если проекта нет в Git, но есть архив.

На **вашем компьютере** упакуйте папку проекта в `.zip`, затем на сервере:

```bash
apt install -y unzip
```

Загрузите архив на сервер (команда выполняется **на вашем компьютере**):

```bash
scp chizhos-app.zip root@IP_СЕРВЕРА:/tmp/
```

Затем **на сервере**:

```bash
unzip /tmp/chizhos-app.zip -d /var/www/ && mv /var/www/chizhos-app /var/www/chizhos
```

```bash
chown -R chizhos:chizhos /var/www/chizhos
```

### Способ В — через SFTP (файловый менеджер)

Подходит, если вы не хотите работать с командами для копирования файлов.

1. Скачайте бесплатную программу **FileZilla** (filezilla-project.org) или **WinSCP** (Windows).
2. Создайте подключение:
   * Протокол: **SFTP**
   * Хост: `IP_СЕРВЕРА`
   * Порт: `22`
   * Пользователь: `root`
   * Пароль: пароль от сервера
3. В правой панели (сервер) перейдите в `/var/www/`.
4. Перетащите папку проекта с левой панели (ваш компьютер) в правую.
5. Переименуйте её в `chizhos`.

**Важно:** папки `node_modules` и `.next` копировать **не нужно** — они большие
и собраны под вашу операционную систему, на Linux работать не будут. Удалите их
перед копированием.

Затем на сервере:

```bash
chown -R chizhos:chizhos /var/www/chizhos
```

### Способ Г — прямое копирование с вашего компьютера (rsync)

Самый быстрый способ, если проект лежит только на вашем компьютере.
Команда выполняется **на вашем компьютере**:

```bash
rsync -av --exclude node_modules --exclude .next --exclude data --exclude backups --exclude .env ПУТЬ_К_ПАПКЕ_ПРОЕКТА/ root@IP_СЕРВЕРА:/var/www/chizhos/
```

Затем **на сервере**:

```bash
chown -R chizhos:chizhos /var/www/chizhos
```

### Проверка, что проект загрузился

```bash
ls /var/www/chizhos
```

Должны увидеть файлы `package.json`, `next.config.mjs`, `ecosystem.config.js`
и папки `src`, `prisma`, `deploy`, `scripts`.

## 5. Настройка проекта (.env)

`.env` — файл с настройками. Он **не входит** в репозиторий (там пароли), его создают на сервере.

### 5.1. Создание файла из образца

```bash
cd /var/www/chizhos && sudo -u chizhos cp .env.example .env
```

### 5.2. Редактирование

```bash
sudo -u chizhos nano /var/www/chizhos/.env
```

Откроется текстовый редактор `nano`. Приведите файл к такому виду:

```ini
DATABASE_URL="file:../data/chizhos.db"

ADMIN_LOGIN="admin"
ADMIN_PASSWORD="ПридумайтеСложныйПароль123"
ADMIN_NAME="Администратор"

ORG_NAME="Название вашей компании"

S3_ENDPOINT=""
S3_REGION="auto"
S3_BUCKET=""
S3_ACCESS_KEY_ID=""
S3_SECRET_ACCESS_KEY=""
S3_PUBLIC_URL=""
```

**Что обязательно изменить:**

| Строка | Что поставить |
|---|---|
| `ADMIN_PASSWORD` | Ваш пароль для входа. **Минимум 12 символов**, буквы разного регистра и цифры |
| `ORG_NAME` | Название вашей организации — оно появится в меню и на странице входа |

**Что менять не нужно:**

* `DATABASE_URL` — путь к файлу базы, уже правильный;
* `S3_*` — оставьте пустыми. Тогда документы будут храниться на диске сервера,
  в папке `public/uploads`. Этого достаточно.

**Как сохранить в nano:**

## 10. Постоянная работа: PM2

Если запускать `npm start` вручную, приложение остановится при закрытии терминала.
PM2 решает эту проблему.

### 10.1. Запуск

В проекте уже есть готовый файл настройки `ecosystem.config.js` — в нём прописаны
имя приложения, порт, ограничение памяти и пути к логам.

```bash
cd /var/www/chizhos && sudo -u chizhos pm2 start ecosystem.config.js
```

Появится таблица со статусом `online`.

### 10.2. Автозапуск после перезагрузки сервера

```bash
sudo -u chizhos pm2 save
```

```bash
pm2 startup systemd -u chizhos --hp /home/chizhos
```

Вторая команда выведет длинную команду, начинающуюся с `sudo env PATH=...`.
**Скопируйте её и выполните** — она регистрирует PM2 в системе автозапуска.

### 10.3. Проверка автозапуска

```bash
reboot
```

Сервер перезагрузится, связь оборвётся. Подождите минуту, подключитесь снова
(`ssh root@IP_СЕРВЕРА`) и проверьте:

```bash
sudo -u chizhos pm2 list
```

Приложение `chizhos` должно быть в статусе `online`. Значит, после любой перезагрузки
сайт поднимется сам.

### 10.4. Команды управления

| Действие | Команда |
|---|---|
| Посмотреть статус | `sudo -u chizhos pm2 list` |
| Перезапустить | `sudo -u chizhos pm2 restart chizhos` |
| Остановить | `sudo -u chizhos pm2 stop chizhos` |
| Запустить снова | `sudo -u chizhos pm2 start chizhos` |
| Смотреть логи в реальном времени | `sudo -u chizhos pm2 logs chizhos` |
| Последние 50 строк логов | `sudo -u chizhos pm2 logs chizhos --lines 50 --nostream` |
| Потребление памяти и CPU | `sudo -u chizhos pm2 monit` |

Выход из просмотра логов и из `monit` — **Ctrl + C**.

## 11. Настройка Nginx

Nginx принимает запросы из интернета (порт 80) и передаёт их приложению (порт 3000).

### 11.1. Копирование готового конфига

В проекте уже есть файл `deploy/nginx/chizhos.conf` с подробными комментариями.

```bash
cp /var/www/chizhos/deploy/nginx/chizhos.conf /etc/nginx/sites-available/chizhos
```

### 11.2. Указание вашего домена

```bash
nano /etc/nginx/sites-available/chizhos
```

Найдите строку:

```nginx
server_name example.com www.example.com;
```

**Если у вас есть домен** — замените на свой:

```nginx
server_name mycompany.ru www.mycompany.ru;
```

**Если домена ещё нет** — поставьте знак подчёркивания, тогда сайт будет отвечать по IP:

```nginx
server_name _;
```

Сохраните: **Ctrl + O**, **Enter**, **Ctrl + X**.

### 11.3. Что делает конфиг (по строкам)

| Строка | Назначение |
|---|---|
| `listen 80;` | Слушать обычный веб-порт |
| `server_name ...;` | На какие домены отвечать |
| `client_max_body_size 25M;` | Разрешить загрузку документов до 25 МБ (совпадает с лимитом приложения) |
| `server_tokens off;` | Не показывать версию Nginx посторонним |
| `access_log` / `error_log` | Отдельные журналы для этого сайта |
| `gzip on;` | Сжимать страницы — открываются быстрее |
| `location /_next/static/` | Файлы оформления кешируются браузером надолго |
| `location /uploads/` | Загруженные документы |
| `location / { proxy_pass http://127.0.0.1:3000; }` | Всё остальное передаём приложению |
| `proxy_set_header Host $host;` | Передать приложению настоящий домен |
| `proxy_set_header X-Real-IP ...` | Передать настоящий IP посетителя |
| `proxy_set_header X-Forwarded-Proto $scheme;` | Сообщить, что снаружи используется HTTPS |

### 11.4. Включение конфига

```bash
ln -sf /etc/nginx/sites-available/chizhos /etc/nginx/sites-enabled/chizhos
```

```bash
rm -f /etc/nginx/sites-enabled/default
```

Вторая команда убирает стандартную страницу-заглушку Nginx.

### 11.5. Проверка и применение

```bash
nginx -t
```

Должно ответить:

```
nginx: configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful
```

Если так — применяем:

```bash
systemctl reload nginx
```

### 11.6. Проверка в браузере

Откройте в браузере:

```
http://IP_СЕРВЕРА
```

Должна появиться **страница входа ChizhOS** с полями «Логин» и «Пароль».

Если появилась — основная часть работы сделана. Уже сейчас можно войти и работать,
а домен и HTTPS настроить позже.

## 12. Подключение домена

### 12.1. Если домена ещё нет

Ничего делать не нужно — система уже работает по адресу `http://IP_СЕРВЕРА`.
Домен можно подключить в любой момент позже, данные при этом не потеряются.

Учтите: **без домена нельзя включить HTTPS** (сертификаты не выдают на IP-адрес),
поэтому пароли будут передаваться в открытом виде. Для постоянной работы домен нужен.

### 12.2. Если домен куплен в Timeweb

1. Панель Timeweb → раздел **«Домены и SSL»**.
2. Наведите курсор на нужный домен → нажмите значок **шестерёнки**.
3. Вкладка **DNS** → кнопка **«Добавить запись»** справа вверху.
4. Заполните:

   | Поле | Значение |
   |---|---|
   | Тип записи | **A** |
   | Значение / IP-адрес | `IP_СЕРВЕРА` |

5. Нажмите **«Добавить»**.
6. Повторите для поддомена `www` (тип A, то же значение).

### 12.3. Если домен куплен у другого регистратора

Два варианта:

**Вариант 1 — делегировать домен в Timeweb.** В панели своего регистратора укажите
NS-серверы Timeweb:

```
ns1.timeweb.ru
ns2.timeweb.ru
ns3.timeweb.org
ns4.timeweb.org
```

Делегирование занимает **от 3 до 24 часов**. После этого управляйте записями по пункту 12.2.

**Вариант 2 — оставить DNS у регистратора.** В его панели создайте A-запись,
указывающую на `IP_СЕРВЕРА`. Так быстрее — обычно 15–60 минут.

### 12.4. Сколько ждать

| Что | Срок |
|---|---|
| Изменение A-записи в существующей зоне | 15 минут – 2 часа |
| Делегирование домена на новые NS | 3–24 часа |

### 12.5. Как проверить, что домен заработал

На **вашем компьютере**:

```bash
ping ВАШ_ДОМЕН
```

В ответе должен быть **IP вашего сервера**. Если показывается другой адрес
или «неизвестный узел» — DNS ещё не обновился, подождите.

Также проверьте в браузере: `http://ВАШ_ДОМЕН` — должна открыться страница входа.

> **Не переходите к разделу 13, пока домен не открывается.** Выпуск SSL-сертификата
> требует, чтобы домен уже указывал на сервер.

## 13. Настройка HTTPS

HTTPS (замочек в адресной строке) обязателен: без него логины и пароли передаются
по сети в открытом виде и их можно перехватить.

### 13.1. Установка Certbot

```bash
apt install -y certbot python3-certbot-nginx
```

### 13.2. Получение сертификата

Замените `example.com` на свой домен:

```bash
certbot --nginx -d example.com -d www.example.com
```

Certbot задаст несколько вопросов:

| Вопрос | Что ответить |
|---|---|
| `Enter email address` | Ваш e-mail (на него придёт напоминание, если сертификат перестанет обновляться) |
| `Please read the Terms of Service... (Y)es/(N)o` | `Y` |
| `Would you be willing to share your email...` | `N` |
| Выбор редиректа (если спросит) | **2** — перенаправлять весь трафик на HTTPS |

Успешный результат: `Congratulations! You have successfully enabled HTTPS`.

Certbot сам изменит конфиг Nginx: добавит порт 443, пути к сертификатам
и перенаправление с HTTP на HTTPS.

### 13.3. Проверка сертификата

Откройте `https://ВАШ_ДОМЕН` — в адресной строке появится замочек.

Проверка из терминала:

```bash
certbot certificates
```

Покажет домены, срок действия и путь к файлам сертификата.

### 13.4. Автоматическое продление

Сертификаты Let's Encrypt действуют **90 дней**. Certbot продлевает их сам —
при установке он создаёт системный таймер.

Проверить, что автопродление включено:

```bash
systemctl status certbot.timer
```

Должно быть `active (waiting)`.

Проверить продление «вхолостую», без реального перевыпуска:

```bash
certbot renew --dry-run
```

Успех: `Congratulations, all simulated renewals succeeded`.

Если когда-нибудь понадобится продлить принудительно:

```bash
certbot renew --force-renewal && systemctl reload nginx
```

## 14. Первый вход в ChizhOS

### 14.1. Адрес системы

| Ситуация | Адрес |
|---|---|
| Домен и HTTPS настроены | `https://ВАШ_ДОМЕН` |
| Только домен | `http://ВАШ_ДОМЕН` |
| Домена нет | `http://IP_СЕРВЕРА` |

### 14.2. Вход администратора

* **Логин:** значение `ADMIN_LOGIN` из `.env` (по умолчанию `admin`)
* **Пароль:** значение `ADMIN_PASSWORD`, которое вы задали в разделе 5

### 14.3. Смена пароля администратора

**Способ 1 — в интерфейсе (обычный):**
**Администрирование → Настройки → Мой пароль** — введите текущий и новый пароль.

**Способ 2 — с сервера (если пароль забыт):**

```bash
cd /var/www/chizhos && sudo -u chizhos npm run create-admin -- --login=admin --password="НОВЫЙ_ПАРОЛЬ"
```

После этого **обязательно обновите** `ADMIN_PASSWORD` в `.env`, чтобы там не остался старый пароль.

> После смены пароля все сессии этого пользователя завершаются — на других устройствах
> потребуется войти заново.

### 14.4. Порядок первичной настройки

**Шаг 1. Создайте автопарк.**
**Администрирование → Автопарки → Добавить парк.** Введите название, например
«Парк №1 — Москва». Это обязательный первый шаг: к парку привязываются
автомобили, водители и пользователи.

**Шаг 2. Создайте пользователей.**
**Администрирование → Пользователи → Добавить пользователя.** Заполните:

* **Логин** — латинские буквы, цифры, символы `.` `_` `-` `@`
* **Имя / ФИО** — как отображать в интерфейсе
* **Пароль** — не короче 6 символов, передайте его сотруднику
* **Роль** — см. таблицу ниже
* **Автопарк** — обязателен для всех, кроме администратора

**Шаг 3. Назначьте роли.**

| Роль | Что доступно |
|---|---|
| **Администратор** | Всё: все автопарки, пользователи, настройки, резервные копии |
| **Менеджер парка** | Все разделы, но данные **только своего** автопарка |
| **Пользователь** | Свой автопарк и **только те разделы**, которые отмечены галочками |

Для роли «Пользователь» появится блок **«Доступные разделы»** — отметьте, что человеку
можно видеть: Dashboard, Автомобили, Водители, Финансы, Расходы, Календарь, Аналитика,
Уведомления.

Неотмеченные разделы не появятся в меню и **будут недоступны по прямой ссылке** —
ограничение действует на сервере, а не только в интерфейсе.

**Шаг 4. Привязка пользователя к автопарку.**
Поле **«Автопарк»** в той же форме. Изменить позже:
**Администрирование → Пользователи → Изменить → Автопарк.**
После сохранения пользователь сразу увидит данные нового парка, а прежний станет недоступен.

**Шаг 5. Внесите рабочие данные.**

1. **Водители** → «Добавить водителя» — ФИО, телефон, права, паспорт, залог.
2. **Автомобили** → «Добавить автомобиль» — госномер, марка, модель, парк.
   Здесь же закрепляется водитель, ставка аренды, дата окончания страховки
   и пробег следующего ТО — из них система построит напоминания.
3. **Карточка автомобиля** (клик по строке) → «Внести платёж» — начисление аренды.
4. **Расходы** → «Добавить расход» — ТО, запчасти, мойка, страховка, штрафы.

> Систему нельзя оставить без администратора: последнего администратора нельзя
> удалить, заблокировать или понизить в роли.

## 15. Обновление проекта

В проекте есть готовый скрипт, который делает всё безопасно и по порядку.

### 15.1. Обновление одной командой

```bash
sudo -u chizhos bash /var/www/chizhos/deploy/update.sh
```

Скрипт выполнит 6 шагов:

1. **Резервная копия** базы и документов — до всех изменений;
2. `git pull` — получение новой версии кода;
3. `npm ci` — доустановка библиотек;
4. `prisma migrate deploy` — применение миграций (**существующие данные сохраняются**);
5. `npm run build` — пересборка;
6. `pm2 restart chizhos` — перезапуск.

### 15.2. Проверка после обновления

```bash
sudo -u chizhos pm2 list && curl -I http://localhost:3000
```

Статус `online` и ответ `200`/`307` означают, что всё в порядке.
Затем откройте сайт в браузере и войдите.

### 15.3. Если обновление сломало систему

Скрипт в конце печатает команду отката. Общий вид:

```bash
sudo -u chizhos pm2 stop chizhos
```

```bash
sudo -u chizhos cp /var/www/chizhos/backups/before-update-ДАТА.db /var/www/chizhos/data/chizhos.db
```

```bash
sudo -u chizhos pm2 start chizhos
```

Посмотреть список доступных копий:

```bash
ls -lh /var/www/chizhos/backups/
```

## 16. Резервное копирование

### 16.1. Что именно нужно резервировать

Данные состоят из **двух частей**, копировать нужно обе:

| Часть | Где лежит | Что содержит |
|---|---|---|
| **База данных** | `/var/www/chizhos/data/chizhos.db` | Автопарки, автомобили, водители, платежи, расходы, пользователи, настройки |
| **Документы** | `/var/www/chizhos/public/uploads/` | Сканы и фотографии: СТС, ПТС, договоры, полисы |

Одной базы **недостаточно** — без папки `uploads` записи о документах останутся,
а сами файлы пропадут.

### 16.2. Копия прямо сейчас

В проекте есть готовый скрипт:

```bash
bash /var/www/chizhos/deploy/backup.sh
```

Копии появятся в `/var/www/chizhos/backups/`:
`chizhos-ГГГГ-ММ-ДД.db` и `uploads-ГГГГ-ММ-ДД.tar.gz`.

### 16.3. Копия через интерфейс

**Администрирование → Резервное копирование → Скачать резервную копию.**

Скачается файл `chizhos-backup-ГГГГ-ММ-ДД.json` — в нём вся база
(без файлов документов). Удобно, чтобы держать копию у себя на компьютере.

### 16.4. Автоматические копии по расписанию

Установим скрипт в систему и настроим ежедневный запуск в 3:30 ночи.

```bash
cp /var/www/chizhos/deploy/backup.sh /usr/local/bin/chizhos-backup && chmod +x /usr/local/bin/chizhos-backup
```

```bash
crontab -e
```

При первом запуске редактор спросит, какой использовать — введите `1` (nano).
Добавьте в конец файла строку:

```
30 3 * * * /usr/local/bin/chizhos-backup >> /var/log/chizhos-backup.log 2>&1
```

Сохраните: **Ctrl + O**, **Enter**, **Ctrl + X**.

Проверка, что скрипт работает:

```bash
/usr/local/bin/chizhos-backup && ls -lh /var/www/chizhos/backups/
```

### 16.5. Копии на другой носитель

Копии на том же сервере **не спасут** при отказе диска или потере сервера.
Раз в неделю скачивайте их к себе. Команда выполняется **на вашем компьютере**:

```bash
rsync -av root@IP_СЕРВЕРА:/var/www/chizhos/backups/ ./chizhos-backups/
```

## 17. Если что-то пошло не так

### Сайт не открывается совсем

**Как определить:** браузер пишет «Не удаётся получить доступ к сайту».

```bash
sudo -u chizhos pm2 list
```

* Статус `online` → проблема в Nginx, см. следующий пункт.
* Статус `errored` или `stopped` → проблема в приложении:

```bash
sudo -u chizhos pm2 logs chizhos --lines 50 --nostream
```

Прочитайте последние строки — там будет причина. Затем:

```bash
sudo -u chizhos pm2 restart chizhos
```

### Ошибка «502 Bad Gateway»

**Что означает:** Nginx работает, а приложение — нет.

```bash
curl -I http://localhost:3000
```

* Нет ответа → приложение не запущено, см. предыдущий пункт.
* Ответ есть → проблема в конфиге Nginx, проверьте порт:

```bash
grep proxy_pass /etc/nginx/sites-available/chizhos
```

Должно быть `http://127.0.0.1:3000`. Если порт другой — исправьте и выполните:

```bash
nginx -t && systemctl reload nginx
```

### Ошибка «403 Forbidden» или «404 Not Found» от Nginx

Скорее всего, не удалена страница-заглушка:

```bash
rm -f /etc/nginx/sites-enabled/default && nginx -t && systemctl reload nginx
```

### Сборка прерывается: «JavaScript heap out of memory»

**Что означает:** не хватило оперативной памяти (типично для тарифа с 1 ГБ).

Создайте файл подкачки — «виртуальную память» на диске:

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
```

```bash
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

Затем повторите сборку:

```bash
cd /var/www/chizhos && sudo -u chizhos npm run build
```

### Ошибка при `npm ci`

**Как определить:** красный текст со словом `error` вместо `added ... packages`.

Удалите и установите заново:

```bash
cd /var/www/chizhos && sudo -u chizhos rm -rf node_modules && sudo -u chizhos npm ci
```

Если пишет про отсутствующий `package-lock.json`:

```bash
cd /var/www/chizhos && sudo -u chizhos npm install
```

### Ошибки базы данных при запуске

```bash
cd /var/www/chizhos && sudo -u chizhos npx prisma migrate deploy
```

```bash
chown -R chizhos:chizhos /var/www/chizhos/data
```

### Забыт пароль администратора

```bash
cd /var/www/chizhos && sudo -u chizhos npm run create-admin -- --login=admin --password="НОВЫЙ_ПАРОЛЬ"
```

### Не загружаются документы

```bash
mkdir -p /var/www/chizhos/public/uploads && chown -R chizhos:chizhos /var/www/chizhos/public/uploads
```

Если файл больше 25 МБ — увеличьте `client_max_body_size` в
`/etc/nginx/sites-available/chizhos` и константу `MAX_SIZE` в
`src/app/api/upload/route.ts`, затем пересоберите проект.

### Certbot не выдаёт сертификат

**Причина почти всегда одна:** домен ещё не указывает на сервер.

```bash
ping ВАШ_ДОМЕН
```

Если IP не совпадает с адресом сервера — дождитесь обновления DNS (раздел 12.4)
и повторите попытку.

### Закончилось место на диске

```bash
df -h / && du -sh /var/www/chizhos/*
```

Чаще всего место занимают старые резервные копии — их можно удалять:

```bash
find /var/www/chizhos/backups -mtime +30 -delete
```

### Сайт стал медленным

```bash
sudo -u chizhos pm2 monit
```

Смотрите потребление памяти. Если приложение постоянно перезапускается из-за лимита
512 МБ — увеличьте `max_memory_restart` в `/var/www/chizhos/ecosystem.config.js`
и выполните `sudo -u chizhos pm2 restart chizhos`.
